# P2I 模型的數值不穩定因素

2026-11-07，RTX 3080、driver 595.71.05。數值都是 0–255 輸出尺度，除非另外註明。

## 摘要

P2I 的 `InputBlock` 用硬性的 4 近鄰 IDW 把雨量站值鋪成整張場，而規則網格會讓大量網格點的第 4、第 5 近鄰距離完全相等。哪一個勝出，取決於座標在 float16 下差一個最小單位的捨入。torch 2.15 改了 float16 `torch.linspace` 的捨入，網格座標因此移動一個最小單位，每個視窗約 2.7% 的網格點換了鄰居，輸出局部差到 86。DK、STDK 沒有這條路徑，至今逐位元不變。

決定：在 G 包重新設計 `InputBlock` 之前，torch 固定在 `>=2.14.1,<2.15`、cu126。

## 現象

把環境從 Python 3.12 + torch 2.14.1+cu126 升到 Python 3.14 + torch 2.15.0+cu132 後，對 `datasets/golden/` 的 MIDAS 10 個事件：

| 模型 | 最大差 | 各事件平均差 | 差超過 2.5 的像素 |
| --- | --- | --- | --- |
| v9 | 63–86 | 0.59–1.26 | 8–18% |
| wopos v9 | 36–66 | 0.69–1.48 | 9–21% |
| DK、STDK | 0 | 0 | 0 |

升級前（torch 2.4.1 → 2.14.1，都是 cu126）v9 最大差只有 2.1。

## 定位

同一個視窗（MIDAS `event_01` 前 16 幀）在新舊環境各跑一次，記錄每一層的輸出。第一個不同的模組是 `InputBlock`，之後的差異只是一路傳下去。把 `InputBlock` 拆成步驟：

| 步驟 | 新舊環境差異 |
| --- | --- |
| 輸入 | 相同 |
| 2 層 `AttentionBlock` | 相同 |
| 雨量站像素的值、雨量站座標 | 相同 |
| 網格點座標（`torch.linspace(0, 1, n, dtype=float16)`） | 128 個值中 18 個、16 個值中 2 個差一個 float16 最小單位 |
| 網格點到最近 4 站的距離 | 最大 8.5e-4 |
| 選到的 4 個鄰居 | 262,144 個網格點中 2.73% 不同 |
| IDW 權重 | 最大 0.008 |
| IDW 輸出（模組輸出） | 最大 0.092，值域 0–0.31 |

把距離改成逐點相減計算、不經過矩陣乘法，差異完全一樣，所以不是 cuBLAS 或 `cdist` 演算法的問題。

## 機制

**同一個座標有兩條計算路線。** 雨量站座標是整數索引除以 (n−1)，以 float32 算出再轉成 float16。網格點座標則是直接用 float16 的 `linspace` 產生。理想上兩者對同一個像素應該完全相等。torch 2.15 的 `linspace` 與雨量站路線在所有索引上都一致；torch 2.14 在 128 點的軸上有 18 個索引、16 點的時間軸上有 2 個索引差一個最小單位。換句話說，舊版的網格點和它所在像素上的雨量站並不完全重合。

**規則網格本身會製造平手。** 所有點都在整數格上，距離平方是 (Δx/127)² + (Δy/127)² + (Δt/15)²。對稱的配置距離完全相同，最常見的是同一站的前一幀與後一幀（Δt = ±1）。在 2.73% 換了鄰居的網格點中，以理想的整數幾何計算，86.3% 的第 4 與第 5 近鄰距離完全相等；74.3% 被換掉的是同一站的不同幀。其餘是差距小於 8e-4 的近似平手。

**平手由捨入決定。** 程式裡沒有真正的平手，因為座標都量化成 float16：在 0.5–1 之間，最小單位是 4.9e-4，約 1/136 幀。理想上相等的兩個距離，量化後會差一點點，哪邊比較近取決於座標怎麼捨入。所以這不是 `topk` 對相同值排序不同，而是座標本身移動了一個最小單位，把原本由捨入雜訊決定的勝負翻過來。

一個實例：網格點 x=26、y=107、t=10。

| 候選 | 舊距離 | 新距離 | 舊版選 | 新版選 |
| --- | --- | --- | --- | --- |
| 站 (20,109) t=10 | 0.049761 | 0.049914 | 是 | 是 |
| 站 (29,114) t=10 | 0.059597 | 0.060043 | 是 | 是 |
| 站 (30,98) t=10 | 0.077937 | 0.077490 | 是 | 是 |
| 站 (20,109) t=11 | 0.082980 | 0.083464 | 是 | 否 |
| 站 (20,109) t=9 | 0.083371 | 0.083073 | 否 | 是 |

舊版網格的 t=10 座標是 0.66699，比雨量站路線的 0.66650 晚一個最小單位，所以 t=11 稍微比較近。新版沒有偏移，換成 t=9 比較近。第 4 個鄰居從後一幀換成前一幀，雨在這兩幀之間變化越快，IDW 的值差越多。這個差異再經過整個網路放大，成為輸出上局部幾十的差。

**為什麼會放大這麼多。** 硬性 top-k 在平手處不連續：座標移動 1e-4，權重 0.2 左右的鄰居就整個換掉。網路之後只看得到 IDW 場，沒有原始觀測可以修正。

## 驗證

| 環境 | v9 最大差 | v9 各事件平均差最大值 | wopos v9 最大差 |
| --- | --- | --- | --- |
| Python 3.12 + torch 2.14.1+cu126 | 2.10 | 0.0096 | 1.65 |
| Python 3.14 + torch 2.14.1+cu126 | 2.10 | 0.0096 | 1.65 |
| Python 3.14 + torch 2.15.0+cu132 | 86 | 1.26 | 66 |
| 同上，但網格座標換回 torch 2.14 的 `linspace` 值 | 2.38 | 0.0095 | — |

Python 版本沒有影響。只把網格座標換回舊值，torch 2.15 + cu132 就回到容差內，所以 `linspace` 是主因；torch 2.15 與 cuBLAS 13 的其他變動合計只多出約 0.3。

## 與作者原始輸出的比較

鎖定的環境（Python 3.14.10、torch 2.14.1+cu126、cuDNN 9.10.2）直接對作者存在 `datasets/infer/` 的輸出。輸入與作者的評估 config 相同：gauge 是 MIDAS 10 個事件，nimrod 是作者的 20 個雷達事件（`datasets/nimrod_h5/author_val`，與 brick 原檔逐位元組相同）。作者標示為「P2I-GAN」的輸出其實是 `p2igan_gan_wopos_v9` 權重產生的。

| 模型 | 輸入 | 事件 | 最大差 | 整體平均差 | 單一事件平均差最大值 | 差超過 2.5 的像素 |
| --- | --- | --- | --- | --- | --- | --- |
| v9（P2I-GAN+） | gauge | 10 | 1.80 | 0.0066 | 0.0097 | 0 |
| v9（P2I-GAN+） | nimrod | 20 | 2.16 | 0.0058 | 0.0089 | 0 |
| wopos v9（P2I-GAN） | gauge | 10 | 1.05 | 0.0080 | 0.0113 | 0 |
| wopos v9（P2I-GAN） | nimrod | 20 | 1.81 | 0.0082 | 0.0123 | 0 |
| DK | gauge、nimrod | 10、20 | 0 | 0 | 0 | 0 |
| STDK | gauge、nimrod | 10、20 | 0 | 0 | 0 | 0 |

DK、STDK 逐位元相同。P2I 最大差約 2，全部在測試容差（最大 2.5、平均 0.02）內。這八組比較都已寫進 `tests/test_golden.py`。

這個差距對 MAE、FSS 等評估指標的影響尚未量測。先前在 Python 3.12 環境重跑 exp1 只證明評估程式對同一批作者檔案算出相同指標（相對差 ≤1.1e-5），exp1 讀的是作者的輸出檔，不是本機的推論。

## 已知的不穩定因素

1. **網格座標的捨入（本報告）。** torch 版本改變 float16 `linspace` 就會觸發。影響 v9、wopos v9；DK、STDK 不受影響。
2. **CPU 與 CUDA 不同精度。** `InputBlock` 在 CUDA 上把座標轉成 float16（距離在 autocast 下以 float32 計算），在 CPU 上全用 float32。座標量化不同，平手的勝負也不同，約 8.6% 的網格點選到不同鄰居。權重是在 CUDA 路徑上訓練的，CPU 推論不代表模型行為。
3. **GPU、驅動、函式庫的小幅漂移。** 同一份程式在不同 torch 或 cuDNN 版本、不同 GPU 上，P2I 輸出差約 2，平均差約 0.01。來源沒有拆解；DK、STDK 在同樣的變動下逐位元不變。
4. **作者輸出與本機重跑的差距。** v9 在本機 3080 重跑與作者存檔差最大 1.97，原因未確認，推測屬於第 3 項。

## 對後續的影響

- 在 G 包之前 torch 固定 `>=2.14.1,<2.15`。任何改動 torch、CUDA 或 GPU 的變更都要重跑黃金測試；P2I 容差維持最大 2.5、平均 0.02，DK、STDK 必須逐位元相同。
- G 包的修正方向：網格點與雨量站座標走同一條計算路線，並一律用 float32 以上；或改用在平手處連續的權重（例如對半徑內所有站做平滑核加權，而不是硬性 top-k）。只換精度不夠，因為規則網格的平手是結構性的，任何硬性 top-k 都會讓結果取決於捨入。
- 這些修正都會改變舊權重的輸出，所以和新資料重新訓練一起做，舊結果之後只靠 tag `baseline-v0` 與目前鎖定的環境重現。
